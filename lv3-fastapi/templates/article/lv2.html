Lv2:【バックエンド】 Railsを用いて食べログ風サイトを作る

このレベルでは、食べログ風サイトをRailsで作りながら、 アプリがリクエストを受け取り、データを読み書きし、HTML の画面を返す流れを理解します。 Rails は「決まった置き場所」と「決まった名前」を大切にするフレームワークです。 迷ったらまず Rails Guides を読み、Rails が想定している書き方を確認してください。

まず読むもの

  • Rails Guides: Getting Started with Rails
  • Rails Guides: Rails Routing from the Outside In
  • Rails Guides: Action Controller Overview
  • Rails Guides: Active Record Basics

ToDo

  1. HTTP の基本として、GET / POST / PATCH / DELETE がそれぞれ何のために使われるか調べる。
  2. bin/rails routes を実行し、URL、HTTP メソッド、controller、action の対応を確認する。
  3. 「食べログネイバー」のトップページとして、飲食店の一覧ページを作る。店名、ジャンル、価格帯、最寄りオフィスを表示する。
  4. 飲食店を保存するための Restaurant、オフィスを保存するための Office、支払い方法を保存するための PaymentMethod の関係を確認する。
  5. 飲食店の詳細ページを作る。食べログ URL、メモ、使える支払い方法、口コミを表示する。
  6. 飲食店の登録フォームを作る。店名、ジャンル、価格帯、食べログ URL、メモ、オフィス、支払い方法を入力して保存できるようにする。
  7. 飲食店の編集フォームを作る。登録済みの情報を変更できるようにする。
  8. 詳細ページに口コミ投稿フォームを追加する。評価、訪問日、コメントを登録し、飲食店ごとに口コミが並ぶようにする。
  9. オフィスやジャンルで飲食店を探しやすくする。余裕があれば一覧ページに絞り込みや並び替えを追加する。
  10. ここまでできたら、会社の近くの飲食店を記録し、探し、口コミを残せる「食べログネイバー」が完成です。

ヒント

  • バックエンドを読むときは「リクエストがどこから入り、どこで処理され、何を返すか」を一本道で追うと理解しやすいです。
  • Rails では URL の入口は config/routes.rb、処理の中心は controller、DB とのやり取りは model が担当します。
  • JSON API は Step3 の内容です。Lv2 ではまず、Rails が HTML の画面を返す基本の流れを追ってください。
  • 一覧ページは RestaurantsController#index、詳細ページは show、登録は new と create、編集は edit と update に分けて考えると整理しやすいです。
  • DB の構造を変えるときは migration、現在の結果を確認するときは db/schema.rb を見ます。
  • 飲食店とオフィスは「1つのオフィスに複数の飲食店」、飲食店と支払い方法は「複数対複数」、飲食店と口コミは「1つの飲食店に複数の口コミ」という関係です。
  • POST や PATCH でうまく値が届かないときは、フォームの input 名、controller の parameter、strong parameters の許可項目を確認してください。
  • CRUD は Create、Read、Update、Delete の略です。多くのバックエンド機能は、この4つの組み合わせで考えられます。

困ったとき

Rails で詰まったら、エラー文だけでなく「今どの層で困っているか」を分けて考えてください。 URL が見つからないなら Routing、データ取得なら Active Record、画面表示なら Action View や Controller のガイドを読みます。 Rails らしい置き場所を知るほど、探す時間は短くなります。
